# About

I’m Rhys. I like engineering work where a model turns into hardware, simulation, and research; the hardware produces data; and the data makes the next design decision a well-defined challenge!

I’m drawn to problems at the intersection of **mechanics, electronics, and software**—work where constraints are real, iteration is expected, and evidence is allowed to override intuition.

## How I work
- **Frame the problem first:** define the objective, constraints, and what “success” means (requirements, acceptance criteria, measurable outputs). :contentReference[oaicite:2]{index=2}
- **De-risk early:** start with the smallest prototype or model that can answer a key question, then scale complexity once the fundamentals hold. :contentReference[oaicite:3]{index=3}
- **Test like it matters:** plan tests around what could fail, log configuration details, and treat instrumentation/sampling/calibration as part of the design. :contentReference[oaicite:4]{index=4}
- **Iterate with traceability:** keep decisions tied to artifacts; that is plots, photos, drawings, configurations; so improvements are explainable and repeatable. :contentReference[oaicite:5]{index=5}
- **Communicate for the reader:** write for ease of parsing the work quickly (goal → method → result → evidence), using visuals as supplementation. :contentReference[oaicite:6]{index=6}
